# 安装与使用指南

本文是「照着做就行」的版本。**动手前请先读 [README 的风险警告](../README.md#风险警告先读这个)。**

---

## 0. 先想清楚

三句话：

1. 这是**不可逆**的。eFuse 一旦熔断就回不来了。
2. **别回锁 Bootloader**，会硬砖，售后拒修。
3. **Root 之后绝对不要升级 DJI Fly**。升级后系统不再正常启动，会落到 fastboot 模式（能救，但很麻烦）。

如果你只是想「让 RC2 能装点别的 App」，先试最轻的方案（临时 root），别一上来就上持久化。

---

## 1. 准备

**你需要：**

- 一台 DJI RC2 遥控器
- 一根能传数据的 USB-C 线
- 一台 Windows / macOS / Linux 电脑
- 电脑上装好 `adb`

**检查 adb 是否可用：**

```bash
adb version
```

没有的话，Windows 下载 [platform-tools](https://developer.android.com/tools/releases/platform-tools)，解压后把目录加进 PATH。

---

## 2. 打开 RC2 的 ADB

RC2 出厂时 ADB 是关的。有两种打开方式：

### 方式 A：用工具（省事）

下载 `ADB-Unlock-RC.exe`，双击运行。它会把 RC2 的网络 ADB 打开。

### 方式 B：手动

如果 RC2 已经能连 USB，并且系统设置里能进开发者选项：

```
设置 → 关于 → 连点版本号 7 次 → 返回 → 开发者选项 → USB 调试
```

RC2 的原厂设置里通常没有开发者选项入口。这时用工具箱里的「跳转隐藏模式打开开发者设置」，或者用工具打开。

**连上之后：**

```bash
adb devices
# 应该看到类似：
# List of devices attached
# 127.0.0.1:5555   device
```

> 如果看到 `unauthorized`，需要在设备上点「允许 USB 调试」。
> 如果列表是空的，见下面的「疑难排查」。

RC2 的 adbd 在 `127.0.0.1:5555` 上是**免认证**的，所以通常不用点授权。

---

## 3. 装工具箱

从 [Releases](https://github.com/456erddgr/rc2-unlock-toolkit/releases) 下载 `RC2-Toolbox-v7.19.apk`：

```bash
adb install -r RC2-Toolbox-v7.19.apk
```

> ⚠️ RC2 的 CPU 是 **32 位 armv8l**。这个 APK 已经包含 `armeabi-v7a`，可以直接装。如果你拿到的是纯 arm64 版本，会装不上或闪退。

装完在设备上找到「RC2 工具箱」图标打开。

---

## 4. 一键部署

打开 App → 首页 → 点「**一键部署**」。

它会按顺序做这些事，并在屏幕上打日志：

| 步骤 | 做了什么 |
|---|---|
| 1 | 建 `/data/adb/ksu` 和 `/data/adb/ksu/bin` |
| 2 | 建 `/data/adb/modules` 模块目录 |
| 3 | 写入 `su` 入口到 `/data/adb/ksu/bin/su` |
| 4 | 写入 `ksud` 兼容 shim |
| 5 | 设超级用户白名单 |
| 6 | 复核上面每一步的真实结果 |

**关键：它会如实报告每一步的输出。** 如果某一步失败了，日志里会写清楚原因，不会假装成功。

### 验证

回到首页，点「**测试 su**」。看到 `uid=0` 就成了。

或者用命令行：

```bash
adb connect 127.0.0.1:5555
adb shell "su -c id"
# uid=0(root) gid=0(root) ...
```

---

## 5. 让 `su` 进入 PATH（可选但很有用）

刚部署完，`su` 只在 `/data/adb/ksu/bin/su`，**普通 App 直接调 `su` 是找不到的**。

在工具箱里点「**安装 su 到 PATH**」。它做的事：

1. 用 tmpfs 遮蔽 `/product/bin`
2. 把里面原本那个 1.4 KB 的脚本复制回去
3. 放进 `su`

这样**所有进程**（包括 zygote 之后新起的）都能解析到 `su`。

点「**开机自愈**」可以让它在每次重启后自动补挂（因为 tmpfs 是内存态，重启就没了）。

> 这是这个项目里最巧的一步。它只遮蔽一个 1.4 KB 的脚本，原件仍然可见，重启后自动恢复，不留痕迹。

---

## 6. 临时 root（推荐先试这个）

如果你不想留下持久改动，用「**临时 root**」那一栏：

- 点「**开启**」→ 建立 root 通道（只写在 `/data/adb/ksu/bin` 和 `/data/local/tmp`）
- 点「**关闭**」→ 撤掉通道

它**不碰 `/system`**，重启后自然消失。

> 建议先用这个试手。确认没问题了再考虑持久化方案。

---

## 7. 系统属性改写

「设置」→「系统属性」：

- 改 `ro.debuggable`、`ro.adb.secure`
- 机型伪装、DPI、时区

用的是 KernelSU 的 `resetprop`，它直接 mmap `/dev/__properties__`，所以：

- 能改 `ro.*` 只读属性（`setprop` 做不到）
- 立即生效，不用重启
- **不依赖内核模块**

⚠️ 默认只在**当前这次开机**内有效，重启回原值。这是 `resetprop` 的固有行为，不是 bug。

---

## 8. 提取 DJI 隐藏的工厂工具

「设置」→「DJI 工具」，用 root 通道启动那些**没导出**的原厂 Activity：

| 包名 | 是什么 |
|---|---|
| `com.dpad.fuli` | 开发助手 |
| `com.dpad.devicetest` | 产测 2.0 |
| `com.dpad.setup` | 设置向导 |

> ⚠️ 启动 `com.dpad.setup`（设置向导）会**导致设备重启**。这是预期行为，不是崩了。

---

## 9. 内核补丁：读这一节可以省下很多时间

**结论：做不到。**

RC2 的内核是 `5.4.210-qgki`，**里面没有 KernelSU 的代码**。KernelSU 的官方 App 可以装，但内核那一半没法从用户态补上。

工具箱里的「内核补丁」按钮**不会**帮你刷内核。它做的是一件诚实的事：

1. 从内置管理器里提取官方的 `ksud` 和 `magiskboot`
2. **只读**盘点内核 / boot 分区 / LKM 支持情况
3. 如果发现 `.ko` 文件，尝试加载
4. dump 真实 boot 镜像，交给 `ksud boot-patch`
5. **把每一步的真实输出原样报告给你**

**它从头到尾不写块设备。** 因为 `fastboot flash` / `erase` 这类写操作在这台机器上没有安全边界 —— 刷错一个 boot 镜像就真的回不来了。

宁可少一个功能，也不做不可逆的操作。

> 要分清两件事：**进 fastboot 是安全的**，`fastboot continue` / `fastboot reboot` 是正常救援手段，App 里有专门的 Fastboot 面板。真正危险的是 `flash`、`erase`、`flashing unlock` 这些写操作。

## 10. 疑难排查

### `adb devices` 列表为空

```bash
# 1. 确认 USB 线是数据线（不是只能充电的）
# 2. 重启 adb 服务
adb kill-server
adb start-server
adb devices

# 3. 手动连网络 ADB
adb connect 127.0.0.1:5555
```

还是不行 → 用 `ADB-Unlock-RC.exe` 重新打开 ADB。

### `unauthorized`

设备上会弹授权框，点「允许」。如果没弹，在设备上撤销 USB 调试授权后重插。

### `su` 命令找不到

`su` 只在 `/data/adb/ksu/bin`。去工具箱点「安装 su 到 PATH」。重启后要重新点，或者开「开机自愈」。

### App 装不上 / 闪退

CPU 是 32 位（armv8l）。确认 APK 含 `armeabi-v7a`。

### 卡在 boot logo / 起不来

**先别慌，也别急着拆机。按顺序排查：**

**第 1 步：确认是不是进了 fastboot。**

```bash
fastboot devices
```

- **能认到设备** → 你的机器好着呢，只是落在了 fastboot 模式。执行任意一条即可正常启动：
  ```bash
  fastboot continue     # 继续正常启动（推荐）
  fastboot reboot       # 直接重启
  ```
  工具箱里的 **Fastboot 面板**就是做这件事的。**这种情况不是变砖。**

**第 2 步：如果 fastboot 认不到，等一等。**

拔插一次 USB，等 1~2 分钟，然后：

```bash
adb devices
```

有反应就说明系统在跑，进一步排查 ADB 相关的问题。没反应的话换一根**数据线**、换一个 USB 口再试一遍 —— RC2 对线和口挺挑。

**第 3 步：确认设备完全无响应之后，才考虑物理方案。**

1. 拆机，从 PCB 测试点进 EDL 9008 模式（需要 1kΩ 电阻 + 万用表 + 焊接）
2. 寄 DJI 官方售后（注意：改装过的机器可能拒修）

> ⚠️ **任何情况下都不要执行 `fastboot flash` / `fastboot erase` / `fastboot flashing unlock`。** 这些写操作才会真正把设备弄到回不来。`continue` 和 `reboot` 是安全的。

## 11. 卸载 / 还原

想撤掉：

1. 工具箱 → 设置 → 「**卸载 su 与 ksud**」
2. 点「**卸载 su from PATH**」（卸载 tmpfs，`/product/bin` 原样回来）
3. 逐个删掉 `/data/adb/ksu`、`/data/local/tmp/nexus-su`
4. 卸载工具箱 App

```bash
adb shell "su -c 'rm -rf /data/adb/ksu /data/local/tmp/nexus-su'"
adb uninstall com.rc2.toolbox
```

> **注意**：如果你解锁过 Bootloader，**不要回锁**。回锁会因 `vbmeta` 校验失败导致硬砖。宁可留着解锁状态。

## 附：常用命令速查

```bash
# 连接
adb connect 127.0.0.1:5555

# root 命令
adb shell "su -c id"
adb shell "su -c 'ls /data/adb/modules'"

# 看设备状态
adb shell "uname -r"
adb shell "getprop ro.build.version.release"

# 看 root 通道日志
adb shell "cat /data/adb/ksu/nexus-boot.log"
```
