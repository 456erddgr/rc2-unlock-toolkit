# 安装与使用指南

本文是「照着做就行」的版本。**主线是 Root ADB**：先把 RC2 的 ADB 变成 root shell，再谈其它。

动手前建议先扫一眼 [README 的「边界与风险」](../README.md#边界与风险)。

---

## 0. 先想清楚

**好消息：这条路不刷机。** 它全程走 ADB 通道，不改系统分区、不解锁 Bootloader、不烧 eFuse。

- ✅ **不需要解锁 Bootloader** —— root 入口跟 BL 状态无关
- ✅ **不会烧 eFuse** —— 熔丝位只在 `fastboot flashing unlock` 时才烧
- ✅ **不写任何分区** —— 载荷全在 `/data/adb-persist`、`/dji_apk/.adb-dev`、`/data/local/tmp`
- ✅ **完全可还原** —— 卸载流程带备份，删掉即回到原样
- ✅ **没有变砖路径** —— 不写分区就不会砖

**两件必须记住的事：**

1. **第 1 步必须真的成功。** `ADB-Unlock-RC.exe` 拿不到 `uid=0` 的 shell，第 2 步无从开始。
2. **root 之后你有能力写分区 —— 但别写。** 工具不写，不代表你手敲的命令安全。

---

## 1. 准备

**你需要：**

- 一台 DJI RC2（平台 `rc331`），开机、解锁屏幕
- 一根能传数据的 USB-C 线（**只能充电的线不行**）
- Windows 10/11 电脑
- 关掉电脑上的手机助手 / 其它 adb 服务（避免抢 5037 端口和独占设备）

**下载两个 exe：**

| 文件 | 大小 | 作用 |
|---|---|---|
| `ADB-Unlock-RC.exe` | 9.2 MB | 前置：打开 RC2 的网络 ADB |
| `Root-ADB.exe` | 20 MB | 核心：装持久化 root ADB |

下载地址见 [DOWNLOADS.md](../DOWNLOADS.md)。

> 两个都需要**管理员权限**运行。它们自带 adb / fastboot / USB 驱动，不用另外装 platform-tools，也不是必须联网。

## 2. 第 1 步：打开 ADB，并确认是 root

双击 **`ADB-Unlock-RC.exe`**，管理员运行，按提示走完。

然后**自己验一下**（这一步不能跳）：

```powershell
adb devices
# List of devices attached
# 127.0.0.1:5555   device

adb shell id
# uid=0(root) gid=0(root) context=u:r:su:s0
```

判据只有一条：**`adb shell id` 必须是 `uid=0(root)`。**

> ⚠️ 如果这里不是 `uid=0`，**先别往下走**。`Root-ADB.exe` 自己也会校验，不满足会直接报错退出 —— 但它不会替你修第 1 步。

### 第 1 步常见问题

| 现象 | 处理 |
|---|---|
| `adb devices` 列表空 | 换数据线、换 USB 口；关掉手机助手；`adb kill-server && adb start-server`；再试 `adb connect 127.0.0.1:5555` |
| `unauthorized` | RC2 的网络 adbd 免认证，出现这个多半是连到了别的设备。`adb devices -l` 确认，`adb disconnect` 后重连 |
| `offline` | DJI 改过系统 adbd，**这个状态是预期的** —— 必须靠第 1 步的工具把通道打开，系统自带 adbd 这条路走不通 |

## 3. 第 2 步：装持久化 Root ADB

双击 **`Root-ADB.exe`**，管理员运行。

它会自动选设备（要求**只有一台**在线），然后把每一步的真实输出打在屏幕上：

| 步骤 | 做了什么 | 失败时的意思 |
|---|---|---|
| 1 | `adb get-state` = `device` | 连接不稳定 |
| 2 | 校验 `uid=0` + `CapEff=0000003fffffffff` | **回第 1 步** |
| 3 | 校验 `ro.product.device = rc331`、SDK、build、SELinux、`ro.serialno`、系统 adbd 哈希 | 机型/固件不匹配 |
| 4 | 安装内置 `dev.rc331.rootadb`，确认没被冻结 | 设备不允许装（少见） |
| 5 | 解出 8 个载荷，比对 `PAYLOAD_SHA256SUMS.txt` | 安装包损坏，重新下载 |
| 6 | push 到 `/data/local/tmp/rc331-root-adb-install`，跑 `bootstrap-install.sh` | 见下面的日志 |
| 7 | 拉起 App 触发 setuid 启动器 | — |
| 8 | 等最多 90 秒，等 `adbd-root` 起来（按硬件序列号认） | 超时：看 `root-adbd.log` |
| 9 | 打印证据 → **自动重启** → 等 75 秒 → 复查 | 复查不过 = 开机自愈没挂上 |

正常结束时你会看到类似：

```
boot_receiver_state=persisted
pid=1234
uid=0(root) gid=0(root)
CapEff:	0000003fffffffff
init_adbd=stopped
tcp_port=5555
```

**第 9 步的重启是故意的** —— 只重启一次才能证明「开机后它真的自己回来了」。等它自动重启完再看结果。

## 4. 验证（四条命令）

```powershell
adb shell id
# uid=0(root) gid=0(root)

adb shell "grep CapEff /proc/\$(pidof adbd-root)/status"
# CapEff:	0000003fffffffff

adb shell getprop init.svc.adbd
# stopped          ← 系统自带 adbd 被停了，正常

adb shell getprop service.adb.tcp.port
# 5555
```

再加一条看日志，确认是「开机重新搭的」而不是「碰巧还活着」：

```powershell
adb shell cat /data/adb-persist/root-adbd.log
```

里面会有一行带时间戳的「完整权限 adbd 就绪 pid=…」。

## 5. 装完能干什么

```powershell
# 读写 /data（比如导出应用数据）
adb shell ls /data/data

# 装 / 卸 App，包括系统预装
adb shell pm install -r -d C:\path\app.apk
adb shell pm uninstall --user 0 com.example.bloat

# 改设置
adb shell settings put global airplane_mode_on 1

# 只读地导分区（安全）
adb shell "dd if=/dev/block/by-name/devinfo of=/data/local/tmp/devinfo.bin"
adb pull /data/local/tmp/devinfo.bin

# 交互式 shell
adb shell
# rc331:/ #            ← 提示符直接是 #
```

> ⚠️ 拿到 root 之后，**每条命令都是 root**。`rm -rf /data/...` 这类没有护栏。写 `/dev/block` 的操作仍然要当成不可逆操作。

## 6. 可选：装 RC2 工具箱（图形界面）

纯命令行已经够用了。想少记命令，再装工具箱：

```powershell
adb install -r RC2-Toolbox-v7.19.apk
```

> ⚠️ **顺序不能反。** 工具箱的「临时 root」只是把 `Root-ADB.exe` 已经装好的 setuid 启动器再执行一次（`TempRoot.java` 注释原话：「设备上先被安装好一套一次性载荷」）。先 Root ADB，再工具箱。

装完打开，四个标签页：

| 标签 | 能做什么 |
|---|---|
| 首页 / 状态 | 一键探测（内核、`/data/adb/ksu`、`su`、KernelSU App）；显示 root 通道双路状态 |
| 超级用户 | 白名单（`root(0)`/`system(1000)`/`shell(2000)` 永放行）；快捷授权；从已装应用勾选；生成 `su` 前端 |
| 模块 | 浏览 `/data/adb/modules`，启用/停用/删除，装模块 zip |
| 设置 / 系统 | 临时 root 开关、`su` 进 PATH、内核补丁**只读**探测、系统属性编辑、DJI 隐藏工厂工具、文件/应用/进程管理、救援 |

### `su` 进 PATH（可选）

`adb shell` 本身是 root，不需要 `su`。但如果想让**普通 App 内部**也能调 `su`：

1. 工具箱 → 设置 → 「安装 su 到 PATH」
2. 原理：用 `mount -t tmpfs` 遮蔽 `/product/bin`（它只装了一个 1.4 KB 的脚本，原件会复刻回去），然后放进 `su`
3. 重启后 tmpfs 消失，点「开机自愈」可自动补挂

**代价很小**：只遮蔽一个 1.4 KB 的脚本，原件仍可见，重启自动恢复。

### 系统属性

「设置」→「系统属性」可以改 `ro.debuggable`、`ro.adb.secure`、机型伪装、DPI、时区等。用的是 `resetprop` 那套（直接 mmap `/dev/__properties__`），所以能改 `ro.*` 只读属性，**不需要重启**。

⚠️ 默认**只在本次开机内有效**，重启回原值。这是 `resetprop` 的固有行为。

### DJI 隐藏工厂工具

「设置」→「DJI 工具」用 root 通道启动没导出的原厂 Activity：

| 包名 | 是什么 |
|---|---|
| `com.dpad.fuli` | 开发助手（28 项） |
| `com.dpad.devicetest` | 产测 2.0（6 项） |
| `com.dpad.setup` | 设置向导（1 项） |

> ⚠️ 启动 `com.dpad.setup` 会让设备**数秒内自动重启**，这是预期行为。

## 7. 内核补丁：读这一节可以省下很多时间

**结论：做不到。**

内核是 `5.4.210-qgki`，**里面没有 KernelSU 的代码**。KernelSU 官方 App 可以装，但内核那一半没法从用户态补上；官方预编译的 LKM 只覆盖 GKI 5.10/5.15/6.1/6.6/6.12。

工具箱里的「内核补丁」不会帮你刷内核。它做的是一件诚实的事：提取 `ksud`/`magiskboot` → **只读**盘点 → 尝试加载 `.ko` → dump boot 交给 `ksud boot-patch` → **把每一步真实输出原样报给你**。

**它从头到尾不写块设备。** 因为刷错一个 boot 镜像，这台机器就真回不来了。

> 注意区分：**进 fastboot 是安全的**，`fastboot continue` / `reboot` 是正常救援手段。危险的是 `flash`、`erase`、`flashing unlock`。

## 8. 卸载 / 还原

跑 `Root-ADB.exe` 的卸载流程（带二次确认），它会：

1. 备份载荷 + 日志到 `/data/local/tmp/rc331-root-adb-removed-<时间戳>/`
2. 打维护标记 `/data/adb-persist/disable-custom-adbd`
3. 删 `/dji_apk/.adb-dev`、`/data/adb-persist`、`/data/local/tmp/librc331_root_adb_agent.so`
4. `adb uninstall dev.rc331.rootadb`
5. 重启

重启后系统回到自带 adbd，`adb shell` 变回普通 shell。

如果还装了工具箱，再补两步：

```powershell
# 先卸载工具箱里可能加过的东西（如果开过「su 进 PATH」）
# 工具箱 → 设置 → 「卸载 su 与 ksud」，然后重启

adb uninstall com.rc2.toolbox
```

> **不要去执行 `fastboot flashing unlock`。** 它会永久烧熔丝位，不可逆。本流程全程不需要解锁 BL。

## 9. 疑难排查

### 重启后 root 没了

```powershell
# 1. 看日志
adb shell cat /data/adb-persist/root-adbd.log

# 2. 看 App 有没有被冻结（会被 BootReceiver 叫不醒）
adb shell dumpsys package dev.rc331.rootadb | Select-String "stopped|notLaunched"
adb shell pm enable --user 0 dev.rc331.rootadb

# 3. 看有没有卸载流程留下的维护标记
adb shell ls /data/adb-persist/disable-custom-adbd
```

维护标记存在时启动脚本会**主动跳过**，这是设计如此。确认要恢复就删掉它。

### 卡在 boot logo / 起不来

**先别慌，也别急着拆机。**

**第 1 步：确认是不是进了 fastboot。**

```powershell
fastboot devices
```

- **能认到设备** → 机器好着呢，只是落在 fastboot。执行任意一条即可：
  ```powershell
  fastboot continue     # 继续正常启动（推荐）
  fastboot reboot       # 直接重启
  ```
  **这不是变砖。**
- 认不到 → 拔插 USB，等 1~2 分钟，再 `adb devices`。

**第 2 步：换线、换口再试。** RC2 对线和口挺挑。

**第 3 步：完全无响应之后，才考虑物理方案** —— 拆机从 PCB 测试点进 EDL 9008（需 1kΩ 电阻 + 万用表），或寄官方售后（改装过的机器可能拒修）。

> ⚠️ **任何情况下都不要执行 `fastboot flash` / `erase` / `flashing unlock`。** `continue` 和 `reboot` 是安全的。

### 设备忽隐忽现

电脑上有别的程序在抢 adb server。关掉手机助手类软件，或者 `adb kill-server` 之后只用一份 adb。

## 附：路径与文件速查

| 路径 | 是什么 |
|---|---|
| `/dji_apk/.adb-dev/adb-root-launcher` | setuid 4755 启动器（「钥匙」） |
| `/dji_apk/.adb-dev/librc331_root_adb_agent.so` | 注入 agent 的持久副本 |
| `/dji_apk/.adb-dev/cap_ptrace_injector` | 带 capability xattr 的桥 |
| `/data/adb-persist/adbd-root` | 我们自己的 adbd（ARM64，0700） |
| `/data/adb-persist/start-root-adbd.sh` | 锁 + 注入 + 超时自愈 |
| `/data/adb-persist/injected-start-root-adbd.sh` | 注入后落地脚本 |
| `/data/adb-persist/root-adbd.log` | **查问题先看这个** |
| `/data/adb-persist/root-adbd.pid` | 当前 adbd-root 的 pid |
| `/data/adb-persist/root-adbd-ready` | 校验过 CapEff 才创建 |
| `/data/adb-persist/disable-custom-adbd` | 维护标记（存在则跳过启动） |
| `/data/adb-persist/.launch-lock/` | 启动锁目录 |

# 命令速查
